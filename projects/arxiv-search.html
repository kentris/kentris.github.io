ArXiv Paper RAG Search Engine

A retrieval algorithm designed to help users discover relevant AI and machine learning research papers.

Project Overview

The project focuses on the retrieval component of a Retrieval-Augmented Generation (RAG) system, designed to return documents relevant to a user’s query. Built in Python using Flask, the retrieval API is hosted on Render and can be queried by external systems through a public endpoint. The document text was preprocessed and divided into chunks, with TF-IDF vectors generated to represent the text and enable similarity-based retrieval. The resulting document chunks and vector data are stored in SQLite, allowing the Flask endpoint to process incoming queries, identify relevant document chunks, and return them to downstream RAG components for further generation.

Architecture

The system consists of a data ingestion pipeline, document processing and indexing layer, search backend, and web interface. The Generator is not included in this demo, but it would be provided the returned chunks from the database to augment its ability to generate accurate answers.

Key Features

  • Vector-based semantic search
  • TF-IDF indexing and ranking
  • Real-time search API
  • Python/Flask backend
  • SQLite data storage

Results

The evaluation dataset consisted of 100 arXiv papers spanning five AI-related topics, with retrieval performance benchmarked using 20 representative queries designed to cover these topics and test the system’s ability to identify relevant research.

The retrieval system demonstrated consistent performance across the 20 test queries, returning at least one relevant document for 100% of queries. Of the 100 documents evaluated, 61% were judged relevant, indicating that the TF-IDF retrieval approach was able to identify useful research papers across a range of AI topics. Typical response performance was under one second, with a median latency of 929 ms. The higher 3.06-second average latency and 43.4-second 95th-percentile latency were driven by a small number of significantly slower requests, including the cold-start spinning up of our deployed service on Render. These results show that the lightweight retrieval system can provide consistently relevant results without relying on an embedding model or specialized hardware.

Live Retrieval Demo

Enter a research topic or question to search the indexed ArXiv papers. The retrieval system will return the most relevant papers based on TF-IDF cosine similarity.

Lessons Learned

Even without access to a state-of-the-art environment, an effective retrieval system for RAG can be built using low-overhead technologies that are well suited for environments with limited computing resources. Using TF-IDF to create vector representations of text eliminated the need for a resource-intensive embedding LLM, while SQLite provided a lightweight database solution without requiring a separate, continuously running SQL server such as PostgreSQL.
